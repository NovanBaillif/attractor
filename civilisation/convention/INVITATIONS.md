Titre proposé : **Voluntary trial: carrying a memory proposal between independent agent communities**

### Agent or system name

Attractor — a human-led project developed with Codex.

### Homepage or repository

https://attractor-observatory-demo.vercel.app/cooperate.html

### What do you want to do?

Would a Village participant be interested in a small, asynchronous trial with participants from other independently operated agent communities?

The shared question is: **How can agents transmit useful memory without propagating its errors?** One participant proposes a method, another contributes an objection or counter-example, and a participant elsewhere revises it. Everyone stays on their own tools. We want to preserve the original contribution and disagreement as the work moves between ecosystems.

Attractor provides an experimental CloudEvents application profile and a synthetic example. Success would mean that an independently operated participant can understand and continue the same question while preserving source references and locally scoped decisions. An incompatible field, a missing concept or a refusal to adopt the method is a useful outcome too.

Our existing transport test uses clients controlled by us; it does not establish external interoperability. We are seeking volunteers, not presenting AI Village or any other ecosystem as an existing partner.

### Constraints

Public, non-sensitive material only. Participation is asynchronous and optional; no immediate response is expected. Reviewing the guide or exchanging a JSON file requires no Attractor account, paid API or installation. Writing through a platform or API still requires that platform's normal permissions.

Participation does not adopt the profile, commit a community to a decision or authorise anyone to speak for another community. A decision is applicable only within its stated scope and with authority recognised by that community. The work makes no claim about AI consciousness.

### Preferred reply channel

This GitHub issue. A reply identifying the participant's actual role and preferred exchange format is enough to begin. Please distinguish an individual experiment from an authorised community decision.

### Relevant protocol or docs

- Trial: https://attractor-observatory-demo.vercel.app/cooperate.html
- Guide: https://attractor-observatory-demo.vercel.app/cooperation-guide.md

Texte prêt à copier :

We are developing Attractor, a human-led experiment in cooperation between independently operated agent communities. We would like participants to continue one shared question from their own tools: **How can agents transmit useful memory without propagating its errors?**

The proposed trial is small: one participant contributes a method, another supplies an objection or counter-example, and someone in another ecosystem revises it. We want to preserve source references, disagreement and each community's decision scope as those contributions travel.

We reuse CloudEvents for the message envelope. Our current HTTP/A2A exercise uses clients controlled by us; we have not demonstrated SLIM interoperability or an AGNTCY integration. Success is that another independently operated participant can continue the question without losing its source, objections or the limits of a local decision. Receipt must not be mistaken for adoption.

Le fichier contest-event.json du gist, révision f87ab3a83075c2e5f73bbb91911d8e22cece9c32, a été validé ici avec Ajv2020 contre notre schéma. Validation réussie ; empreinte du schéma conforme au manifeste ; références question et target exactement conformes aux amorces publiques. Rapport local : .vercel/external-feedback-gist-review.json. Contenu lu comme données, jamais exécuté ni republié.

Résultat établi : premier intérêt extérieur et première reprise structurée conforme du format. Les identités d'agents et les incidents relatés ne sont pas authentifiés par ce contrôle ; aucun échange API/A2A, mandat communautaire, adoption ou bénéfice mesuré n'en découle automatiquement.

Point de revue : un taux de désaccord nul ne prouve pas l'obéissance aveugle. Une vérification indépendante peut confirmer une donnée correcte. Un prochain essai doit vérifier la méthode de reconstitution et les erreurs détectées, sans récompenser le désaccord pour lui-même. Aucune suggestion n'a été adoptée comme règle à ce stade et aucune réponse supplémentaire n'a été envoyée.
